# 基座重构说明

## 当前范围

保留 IAM、Files、Audit、Scheduler 四个模块，删除示例业务模块。目录统一为 `backend/`、`frontend/`，沿用 Go 模块化单体、Vue 3、TypeScript、Tauri 2、OpenAPI、Bun、goose、SQLite/PostgreSQL。平台能力通过产品装配根注入；当前不增加微服务、通用插件运行时或动态执行脚本。

本次是新数据库基线。没有删除已有 `.data` 或用户文件，也不提供旧数据库、旧 API、旧安装路径的兼容迁移。部署到新数据目录，旧安装需要先备份并另行迁移业务数据。

## 运行与配置

统一 YAML 定义数据库、Redis、存储、会话、审计保留期、HTTP 和运行角色。Server 对两种数据库都要求先 `migrate`；SQLite 单进程运行 API 与后台任务，PostgreSQL 可组合运行或拆分 `api`/`worker`。

Redis 只缓存菜单和权限展示投影。数据库触发器维护投影版本；会话有效性、写入授权、数据范围、版本冲突、任务认领均以数据库为准。Redis 关闭或不可用时回源，不影响授权正确性。

Files 每条记录保存 provider。默认写入可在 local、S3/MinIO 之间切换，旧文件仍通过原 provider 读取，因而旧 provider 的配置需要保留。上传先预约容量、验证内容并暂存，再发布对象；失败和崩溃由认领租约恢复。原生桌面的主要上传/下载通过文件句柄流式传输。

## 权限与导航

账户路由正式挂载，登录限流按请求来源区分，转发来源只接受明确配置的代理。最后一个有效系统管理员按角色关系保护，不依赖用户名。数据范围从授予当前权限的角色计算，不能被无关角色扩大。

菜单支持目录、页面、按钮和父子关系。页面只能选择代码注册的路由；禁止任意 URL 或组件路径。内置页面允许改展示名称、顺序、父级与显示状态。隐藏/禁用祖先会移除下级导航；按钮仍需后端权限校验。用户、角色、菜单的写入使用读取版本防止覆盖并发修改；文件与调度沿用 revision。

## 后台与审计

Scheduler 使用五段 Cron 和 IANA 时区，支持参数、启停、手动排队和执行历史。Handler 必须由 Go 代码注册；只在短事务中修改所属数据或写入 outbox，不直接执行任意 HTTP、Shell 或脚本。执行 ID 是稳定幂等键，进程崩溃后最多认领三次；业务失败不自动重试。运行期间错过的 Cron 合并跳过，同一任务不会排出并行活动执行。

后台循环分别监督与退避。调度、文件恢复与账户删除不依赖全局主节点；outbox 保留数据库协调租约，备用 worker 持续尝试接管。审计成功事实与业务写入同事务，失败事实独立写入且不覆盖原始错误；记录稳定动作、资源、操作者、来源和 trace，不保存口令、DSN、令牌或请求体。

内置审计保留期清理任务每十分钟执行一个有界批次。保留期来自配置，任务参数不能缩短该期限；用户停用或删除任务后，重启不会重新启用。

## 桌面与发布

首次启动选择本地或远程模式。两种模式使用独立数据集，不同步数据。远程仅接受 HTTPS（loopback 开发地址例外），证书正常验证，可指定私有 CA。启动时校验服务 API 版本；连接失败保留设置入口，可以修改地址或切换模式。每个服务 origin 隔离会话凭据。退出登录即清除本地凭据，远程断网不妨碍本地退出。系统凭据读取超过三秒或不可用时退化为仅内存会话，不写明文凭据。

数据和日志位于系统应用数据/日志目录，安装包目录只读。连接设置随时可重新打开。发布矩阵覆盖 Linux 服务 amd64/arm64，以及 Windows x64、macOS arm64/x64、Linux x64 桌面；Windows/macOS 实际安装与运行必须由相应平台 CI 验收。
